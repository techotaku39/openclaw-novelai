# OpenClaw + NovelAI

## 非技术用户使用指南

这份指南只讲日常使用和如何向 AI 下指令。

你可以把 OpenClaw 理解成一个会操作 NovelAI 的助手：你用中文描述想做什么，它会选择合适的功能、读取你的小说资料、生成文字或图片，并保存结果。

## 一句话用法

直接告诉 AI：

```text
我想做什么 + 使用哪些资料/图片 + 希望得到什么结果 + 是否先估算消耗
```

例如：

```text
读取第三章内容，找出适合配图的场景，先列计划和预计消耗，不要马上生成。
```

涉及生图或图片处理时，推荐加上：

```text
先告诉我使用的模型、图片尺寸、生成次数和预计消耗，等我确认后再执行。
```

## 一、小说写作

### 创建一本小说

```text
创建一个名为《星海边境》的小说项目。
```

之后可以继续补充：

```text
这个故事是近未来太空冒险，主角是林澈和顾遥，整体风格冷峻但有希望感。
请把这些作为本项目的长期设定。
```

### 保存故事设定

可以把资料分成四类告诉 AI：

- 世界观、人物硬设定、已经确定的事实；
- 当前剧情进展；
- 名词、地点、组织和背景资料；
- 写作人称、语气和风格。

示例：

```text
把下面内容整理成这个项目的人物和世界观设定。没有得到我确认前，不要覆盖原有设定。
```

### 继续写章节

```text
读取《星海边境》的项目设定和第二章，继续写第三章开头 1000 字。保持第三人称，不改变已经确定的人物关系。
```

### 规划剧情

```text
根据目前的剧情，提出三个第三章走向。每个方案写出主要冲突、人物选择和结尾悬念，先不要写正文。
```

### 改写文字

```text
把这段文字改得更紧张、更有画面感，但不要改变事件顺序、人物性格和结局。
```

也可以指定方向：

```text
保留原意，改成克制、冷峻的科幻小说风格。
```

### 检查故事问题

```text
检查这一章有没有时间线矛盾、人物设定冲突、视角跳跃或前后不一致，只列出问题和建议，不要直接修改正文。
```

### 总结章节

```text
总结第三章：列出发生的事件、人物状态变化、重要伏笔和仍未解决的问题。
```

### 更新剧情记忆

```text
根据刚才确认的第三章内容，生成一份剧情记忆更新稿。先展示给我，确认后再保存。
```

建议始终让 AI“先展示、后保存”，尤其是世界观和人物设定。这样不会因为 AI 的推测改变正式设定。

## 二、文字模型怎么选

### Xialong

适合小说续写、故事延展和自然的段落接续：

```text
使用 Xialong，沿用项目设定，继续写这一段。
```

### GLM-4.6

适合需要更明显对话感、分析感或思考过程的任务。建议让 AI 使用流式输出：

```text
使用 GLM-4.6 流式完成这次剧情分析。
```

如果你不确定选哪个，可以直接说：

```text
根据任务类型帮我选择合适的 NovelAI 文字模型，并说明理由。
```

## 三、文生图

文生图就是“只用文字描述生成一张新图片”。

```text
生成一张月光港口的动漫插图：夜晚、薄雾、木船、远处灯塔、蓝色月光、电影感构图。使用 V5，512x768，只生成一张，先估算消耗，确认后再生成。
```

描述图片时，按下面顺序说会更容易得到想要的结果：

1. 画面主体：谁或什么；
2. 外观：发色、服装、年龄、材质；
3. 动作：正在做什么；
4. 地点和时间：室内、街道、森林、清晨、夜晚；
5. 镜头和构图：近景、全身、俯视、角色在左侧；
6. 氛围和光线：温暖、压抑、雾气、逆光；
7. 不想出现的内容：文字、水印、模糊、额外人物等。

例如：

```text
生成一张银发少女站在雨夜车站的半身插图。她穿深蓝色长风衣，手里拿一把透明雨伞，霓虹灯倒映在地面，气氛安静而孤独。不要文字、不要水印、不要额外人物。
```

## 四、多角色生图

如果画面中有多个人，要明确说出每个人的外观和位置：

```text
生成两个角色站在雨夜街道的画面：
女孩银发、蓝色外套，站在左侧；
男孩黑发、红色围巾，站在右侧；
两个人面对面，保持人物边界清楚。使用 V4.5，先估算消耗。
```

如果角色已经在项目中设定过，可以说：

```text
使用项目里的林澈和顾遥设定，生成他们在月光港口第一次见面的插图。林澈在左，顾遥在右，保持服装和发型一致。
```

## 五、图生图

图生图是“拿一张已有图片作为基础，再生成一个变化版本”。

先把图片发给 AI，然后说：

```text
用这张图片做图生图，保留人物脸部、姿势和主要构图，把背景改成雨夜街道。改动不要太大，输出为新图片，不要覆盖原图。
```

常见用途：

- 换背景；
- 换衣服；
- 改变光线和天气；
- 改成另一种画风；
- 保留人物姿势，生成不同场景；
- 生成同一画面的多个变体。

控制改动程度：

```text
尽量贴近原图，只改变背景。
```

```text
允许较大幅度重新设计，但保留人物身份和整体构图。
```

如果你知道参数，也可以直接指定：

```text
Strength 使用 0.3，尽量保持原图。
```

## 六、局部重绘

局部重绘是“只修改图片中的某一块区域”。需要把原图和遮罩图一起发给 AI。

```text
使用这张原图和 mask.png，只修复右手，其他区域尽量保持不变。使用 V4.5 局部重绘模型，先估算消耗。
```

白色区域通常表示“需要重绘”，黑色区域表示“尽量保留”。

常见用途：

- 修复手、脸、眼睛；
- 修改衣服上的局部细节；
- 删除画面中的小物体；
- 在指定位置添加花朵、武器或饰品；
- 修复背景的一小部分。

描述局部内容时要具体：

```text
只把遮罩区域改成一朵小型蓝色花朵，花朵自然地握在角色手中，不要改变手臂和背景。
```

## 七、Vibe Transfer 风格迁移

Vibe Transfer 用一张参考图的整体风格、色彩和氛围，帮助生成另一张图。它不一定复制参考图中的人物或构图。

```text
使用这张参考图提取画风和色彩氛围，再生成一张月光森林中的小屋。不要复制参考图人物，使用 V4.5，先估算消耗。
```

如果希望更偏向参考图：

```text
让参考图风格影响更明显，但保留新场景的构图和内容。
```

如果只想借鉴一点感觉：

```text
只轻微参考这张图的色彩和光线，不要改变新场景的主体。
```

Vibe 主要适用于 V4/V4.5。若选择 V5，应先让 AI 确认当前工具是否支持这种参考方式。

## 八、角色参考图

如果工具提供角色参考功能，可以这样说：

```text
用这张角色参考图保持人物的脸部、发型和服装特征，生成她在雪山车站的全身图。背景和动作可以改变。
```

想保持画风也要明确说：

```text
同时参考人物外观和原图画风，但不要复制原图构图。
```

角色参考和 Vibe Transfer 是不同概念：

- 角色参考：重点保持“这个人是谁”；
- Vibe Transfer：重点借鉴“图片是什么感觉”。

## 九、标签建议

如果你不知道 NovelAI 标签怎么写，可以让 AI 帮你补全：

```text
我想生成“银色长发、雨夜、蓝色制服、港口灯光”的图片，请先给我一份 NovelAI 标签 Prompt，并解释每组标签的作用，不要立即生图。
```

确认后：

```text
使用刚才确认的标签生成一张 512x768 图片，先估算消耗。
```

## 十、Director 图片工具

Director 是对已有图片做特定处理。先把图片发给 AI，再说明动作。

### 转线稿

```text
把这张图片转换成干净的黑白线稿，保留原图，结果保存为新图片。
```

### 转素描

```text
把这张图片转换成铅笔素描效果，保留原图。
```

### 移除背景

```text
移除这张图片的背景，保留人物主体，输出透明背景图片，原图不要覆盖。
```

### 清理画面

```text
清理图片中的杂物和不需要的画面干扰，尽量保持人物和构图不变。
```

### 给线稿上色

```text
给这张线稿上色：银色头发、深蓝色衣服、暖黄色背景光。保留线稿和原图。
```

### 改变情绪

```text
让图中人物表现出开心、放松的情绪，尽量保持脸部特征和画面构图。
```

## 十一、ControlNet 标注图

ControlNet 标注图是给后续生成提供结构参考的辅助图，不是普通的美化图。

```text
为这张图片生成 fake_scribble 线稿标注图，原图保留。
```

也可以先让 AI 解释：

```text
根据这张图片，哪一种 ControlNet 标注更适合保持人物姿势？请先说明，不要执行。
```

## 十二、图片放大和增强

### 专用放大

```text
把这张图片进行 2 倍专用放大。先检查当前放大工具是否可用，并说明预计消耗。
```

专用放大和重新生成不同：专用放大更偏向保留原始像素和细节。

### 大尺寸图生图增强

如果你想让 AI 在更高分辨率下重新细化：

```text
用图生图增强这张图片，输出更高分辨率版本，尽量保持原构图和人物，不要覆盖原图。请说明这属于重新生成，不是像素保真的专用放大。
```

## 十三、账户和费用

查询账户：

```text
查询我的 NovelAI 订阅状态和账户信息，只查询，不生成图片。
```

估算费用：

```text
估算使用 V5、512x768、8 steps、1 张图片的大致 Anlas 消耗，只估算，不生成。
```

批量任务：

```text
我要为第三章生成 5 张插图。请先列出每张图片的场景、模型、尺寸、生成次数和预计总消耗，等我确认后再开始。
```

## 十四、章节配图完整流程

推荐分两次说，不要一开始就让 AI 批量生成。

第一步：规划。

```text
读取第三章和项目中的人物设定，找出最适合配图的关键场景。每个场景说明人物、地点、动作、构图、推荐模型和预计消耗。先不要生成。
```

第二步：执行。

```text
按我确认的前两个场景生成插图。一次生成一张；每次开始前告诉我模型、尺寸、steps 和预计消耗；生成后保存为新文件，并记录 Prompt、Seed 和输出路径。
```

## 十五、保存和整理结果

每次生成后可以说：

```text
把刚才的图片保存为新的项目素材，不要覆盖原图，并记录使用的模型、Prompt、负面 Prompt、Seed、尺寸和生成类型。
```

整理章节素材：

```text
把刚才生成的图片标记为第三章场景图，并列出每张图片的文件名和对应场景。
```

检查记录：

```text
列出这个项目最近生成的图片、使用的模型和 Prompt，不要显示任何密钥信息。
```

## 十六、最实用的指令模板

### 只想聊天写作

```text
读取当前小说项目设定，继续写这一段。保持既有人物性格和叙事风格，写完后列出本段新增的剧情事实。
```

### 只想生成一张图

```text
生成一张【主体】在【地点】进行【动作】的【画风】插图，画面氛围是【氛围】，使用【模型】和【尺寸】。先估算消耗，确认后再生成。
```

### 只想修改图片

```text
使用这张图片，把【要修改的内容】改成【目标效果】，尽量保留【必须保留的内容】，输出为新图片，不要覆盖原图。
```

### 想让 AI 先规划

```text
先分析需求并给出方案、模型、参数、预计消耗和可能的取舍，不要执行任何会产生费用的操作。
```

### 想让 AI 保守操作

```text
所有原文件都保留；生成前先询问我；一次只执行一个操作；完成后报告输出文件和使用的参数。
```

## 十七、最后记住三件事

1. 你可以直接用中文描述需求，不需要记 API 或工具名称。
2. 生图、图生图、局部重绘和 Director 都可能消耗 Anlas，批量操作前先让 AI 估算并等待确认。
3. 明确要求“保留原图、输出新文件、记录参数”，以后更容易复现和管理作品。
