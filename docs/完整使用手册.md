# OpenClaw + NovelAI

## 人类使用手册

这份手册写给实际使用 OpenClaw 的人。它告诉你：第一次如何安装和配置、平时应该怎样对 AI 下指令、每个功能能做什么，以及遇到问题时如何判断。

本手册对应压缩包里的 `openclaw-novelai` Skill 和 `novelai-image-mcp==0.4.0` 配置示例。

## 一、先理解它们各自负责什么

这套方案不是一个单独的聊天软件，而是三个部分一起工作：

| 部分 | 负责的事情 |
| --- | --- |
| OpenClaw | 接收你的消息、调用 AI、读写文件、连接外部工具 |
| `SKILL.md` | 告诉 AI 什么时候使用哪个工具，以及安全和失败处理规则 |
| NovelAI 文本模型 | 小说续写、改写、剧情分析和文字生成 |
| NovelAI Image MCP | 文生图、图生图、局部重绘、Vibe、Director 等图片操作 |
| `project_state.py` | 管理小说项目的设定、记忆、Lorebook、风格和生成记录 |

因此，安装 Skill 后，你不需要记住复杂的 API 请求。正常情况下直接用自然语言告诉 OpenClaw 你想做什么即可。

## 二、第一次安装

### 1. 解压

把压缩包解压到一个稳定目录，例如：

```text
D:\OpenClaw\openclaw-novelai\
```

解压后，目录根部应该能看到：

```text
SKILL.md
README.md
docs\
examples\
scripts\
tests\
```

不要只把其中的 `SKILL.md` 单独拿出来；这个 Skill 还会用到 `scripts` 目录里的项目状态工具。

### 2. 准备软件

目标机器需要准备：

- OpenClaw；
- Python 3.13；
- `uv` / `uvx`；
- 一个有有效订阅的 NovelAI 账户；
- NovelAI Persistent API Token。

当前配置固定使用 `novelai-image-mcp==0.4.0`，该版本要求 Python 3.13–3.13.x。Python 3.12 不能直接当作这个 MCP Server 的运行环境。

### 3. 配置 Token

推荐在 Windows 的“环境变量”界面中配置：

1. 打开“编辑系统环境变量”；
2. 点击“环境变量”；
3. 在“用户变量”中新建：
   - 变量名：`NOVELAI_TOKEN`
   - 变量值：你的 NovelAI Persistent API Token
4. 保存并重新打开终端以及 OpenClaw Gateway。

不要把 Token 发给 AI，不要写进本手册、Prompt、命令行、普通配置文件、日志或生成记录。若 Token 曾经出现在聊天里，使用结束后应在 NovelAI 账户中撤销并重新生成。

### 4. 安装本地 Skill

当前 OpenClaw CLI 支持从“已解压的本地目录”安装 Skill。示例：

```powershell
openclaw skills install "D:\OpenClaw\openclaw-novelai" --as openclaw-novelai
```

然后检查：

```powershell
openclaw skills list
openclaw skills info openclaw-novelai
openclaw skills check
```

如果你的 OpenClaw 版本不支持本地安装，也可以把解压后的目录加入 `skills.load.extraDirs`。目录必须直接包含 `SKILL.md`，不要多套一层目录。

OpenClaw 的 Skill CLI 说明：<https://github.com/openclaw/openclaw/blob/main/docs/cli/skills.md>

### 5. 配置文字模型和图片 MCP

压缩包中的：

```text
examples\openclaw.config.example.json5
```

是配置骨架，不是一定可以原样覆盖的完整配置。请让 AI 将其中相关字段合并到现有 OpenClaw 配置，不要覆盖已有的频道、模型和权限设置。

核心关系如下：

```json5
models: {
  providers: {
    novelai: {
      baseUrl: "https://text.novelai.net/oa",
      api: "openai-completions",
      apiKey: "${NOVELAI_TOKEN}",
      models: [
        { id: "xialong-v1", name: "NovelAI Xialong", input: ["text"] },
        { id: "glm-4-6", name: "NovelAI GLM-4.6", input: ["text"] },
      ],
    },
  },
},
mcp: {
  servers: {
    "novelai-image": {
      command: "uvx",
      args: ["--from", "novelai-image-mcp==0.4.0", "novelai-image-mcp", "serve"],
      env: {
        NOVELAI_TOKEN: "${NOVELAI_TOKEN}",
      },
    },
  },
},
```

`apiKey` 和 `env.NOVELAI_TOKEN` 都只是引用环境变量，不要将 `${NOVELAI_TOKEN}` 替换成真实 Token 写入文件。不同 OpenClaw 版本的 SecretRef 和环境变量插值规则可能不同，应让 AI 先检查当前版本文档。

如果启用了沙箱，通常还需要允许 MCP 工具：

```json5
tools: {
  sandbox: {
    tools: {
      alsoAllow: ["bundle-mcp"],
    },
  },
},
```

### 6. 检查 MCP 是否连接成功

重启 OpenClaw Gateway 后，让 AI 或在终端执行：

```powershell
openclaw mcp doctor novelai-image --probe
openclaw mcp probe novelai-image --json
```

成功时，应该能发现类似以下工具：

```text
generate_image
image_to_image
inpaint
upscale_image
director_tool
annotate_image
suggest_tags
encode_vibe
get_subscription
get_user_data
estimate_anlas_cost
```

工具可能显示成带服务器前缀的名字，例如 `novelai-image__generate_image`，这是正常的。

OpenClaw MCP 说明：<https://github.com/openclaw/openclaw/blob/main/docs/tools/mcp.md>

## 三、第一次对话应该怎么做

安装好后，先不要马上批量生图。把下面这段发给 OpenClaw：

```text
请先检查 openclaw-novelai Skill 是否已加载，并列出当前可用的 NovelAI 文本模型和图片 MCP 工具。只做连接和工具发现检查，不要生成图片。确认 NOVELAI_TOKEN 已从安全环境读取，但不要显示它的值。
```

然后做一个不生成图片的账户检查：

```text
查询 NovelAI 订阅状态，并估算一张 512x768、8 steps 图片的大致消耗。先不要生成图片。
```

如果 AI 能列出工具、查到订阅并给出估算，说明基础配置大体正常。

## 四、小说项目功能

### 创建项目

```text
创建一个名为“星海边境”的小说项目，之后所有章节都使用这个项目目录。
```

Skill 会使用 `project_state.py` 创建类似这样的目录：

```text
novelai-projects/
└─ 星海边境/
   ├─ canon.md
   ├─ memory.md
   ├─ lorebook.md
   ├─ style.md
   ├─ chapters/
   ├─ images/
   └─ metadata\generations/
```

这些文件的用途：

- `canon.md`：不可随意改变的世界观、人物设定和硬性事实；
- `memory.md`：截至目前的剧情摘要和状态；
- `lorebook.md`：名词、地点、组织、背景知识；
- `style.md`：叙事人称、语言风格、节奏和格式；
- `chapters/`：章节正文；
- `images/`：章节插图和编辑后的图片；
- `metadata/generations/`：模型、Seed、Prompt 等生成记录。

### 继续写作

```text
读取“星海边境”项目的 canon、memory、lorebook 和 style，继续写第三章。保持第三人称，先写 800 字，不要改变已经确定的人物设定。
```

### 先做剧情规划

```text
读取第二章和项目上下文，列出三个第三章剧情走向，每个说明冲突、人物变化和结尾钩子。先不要写正文。
```

### 改写和审阅

```text
检查第三章是否存在人物设定冲突、时间线问题和视角跳跃。只列问题和修改建议，不要直接改文件。
```

```text
把这段文字改得更紧张，保留所有剧情事实和人物关系，不要改变结局。
```

### 更新记忆

```text
总结第三章，给出 memory.md 的更新草稿。先展示草稿，等我确认后再写入文件。
```

建议保留“先展示、后写入”的习惯，尤其是 `canon.md` 和 `memory.md`。这样可以防止 AI 把一次推测误写成正式设定。

## 五、图片功能

### 通用原则

每次生图前，建议明确告诉 AI：

- 使用哪个模型；
- 图片尺寸；
- steps 和样本数；
- 正向 Prompt；
- 负面 Prompt；
- 是否使用参考图；
- 是否先估算 Anlas；
- 输出是否保存为新文件。

如果你没有指定参数，可以让 AI 先给出方案，不要让它默认批量生成。

常用模型：

| 用途 | 模型 ID |
| --- | --- |
| V5 文生图 | `nai-diffusion-5-full` |
| V4.5 文生图和图生图 | `nai-diffusion-4-5-full` |
| V4.5 局部重绘 | `nai-diffusion-4-5-full-inpainting` |

512x768 是低成本测试尺寸；尺寸通常需要是 64 的倍数。

### 文生图

```text
生成一张月光港口的动漫插图：夜晚、雾气、木船、远处灯塔、电影感构图。使用 V5，512x768，8 steps，生成前先估算 Anlas，确认后再生成。保存为新的图片文件并记录模型、Seed 和 Prompt。
```

对应工具是 `generate_image`。

### 多角色

```text
生成两个角色站在雨夜街道的画面：女孩银发蓝衣位于左侧，男孩黑发红围巾位于右侧。使用 V4.5，保持两个角色的位置区分，先估算消耗。
```

AI 应使用角色提示词和位置参数，而不是把两个人的描述混成一段普通 Prompt。

### 图生图

先把图片上传给 OpenClaw，或告诉 AI 它能访问的文件路径：

```text
使用这张图片做图生图，保持人物脸部和主要构图，把背景改成雨夜街道。Strength 设为 0.3，原图不要覆盖，输出保存为新文件。
```

对应工具是 `image_to_image`。通常 Strength 越低，生成结果越接近原图；Strength 越高，改动越明显。

### 局部重绘

需要一张原图和一张遮罩图：

```text
使用 portrait.png 和 mask.png，只重绘右手，其他未遮罩区域尽量保持不变。使用 V4.5 inpainting 模型，生成前先告诉我预计消耗。
```

对应工具是 `inpaint`。通常白色区域表示需要重绘，黑色区域表示保留；如果使用的 MCP 工具说明给出不同约定，以工具实际签名为准。

### Vibe Transfer

```text
使用 style.png 提取画面风格，然后生成一张月光森林插图。使用 V4.5，风格参考强度 0.6，先估算消耗。
```

对应流程是 `encode_vibe` 后再调用 `generate_image`。Vibe 主要适用于 V4/V4.5，不要默认套用到 V5。

### 标签建议

```text
我想画“银色长发、雨夜、蓝色制服、港口灯光”，请先用 NovelAI 标签建议补全 Prompt，再把最终 Prompt 展示给我，不要立即生成。
```

对应工具是 `suggest_tags`。

### Director 工具

```text
把这张图片转换成线稿，原图保留，结果保存为新文件。
```

```text
移除这张图片的背景，原图不要覆盖。
```

```text
把这张线稿上色，头发改成银色，保留线稿和原图。
```

```text
让图中人物表现出开心的情绪，生成前先说明会产生一次图片处理请求。
```

支持的 Director 类型：

- `lineart`：线稿；
- `sketch`：素描；
- `bg-removal`：移除背景；
- `declutter`：清理杂物或画面干扰；
- `colorize`：上色；
- `emotion`：改变情绪。

对应工具是 `director_tool`。

### ControlNet 标注

```text
为这张图生成 fake_scribble ControlNet 标注图，原图保留。
```

对应工具是 `annotate_image`。它用于生成控制图，不是普通的美化或放大工具。

### 放大

理论用法：

```text
把这张图片进行 2 倍专用放大，先检查当前 upscale 工具是否可用。
```

本次实测中专用 `/ai/upscale` 接口返回 404，所以不能默认认为 `upscale_image` 可用。如果失败，可以改为：

```text
用图生图在更高分辨率下增强这张图片，尽量保持原构图。请明确说明这不是像素保真的专用放大。
```

图生图增强和专用放大是两种不同操作。

## 六、章节自动配图

推荐这样下指令：

```text
读取“星海边境”第三章和项目设定，找出适合配图的关键场景。列出每个场景的时间、地点、人物、动作、构图、推荐模型和预计消耗。只做规划，不生成。
```

确认方案后：

```text
按刚才确认的前两个场景生成插图。一次只生成一张；每张都先报告模型、尺寸、steps 和预计消耗；生成后保存为新文件，并记录 Prompt、负面 Prompt、Seed 和输出路径。
```

这样做比直接说“给第三章配十张图”更安全，因为批量图片会消耗较多 Anlas，也更容易出现角色和画风不一致。

## 七、生成记录和文件

可以要求 AI：

```text
把刚才生成的图片记录到这个项目的 metadata/generations，并确保记录中不包含 Token 或 Authorization。
```

生成记录应包含：

- 时间；
- 工具名称；
- 模型；
- Prompt 和负面 Prompt；
- 尺寸、steps、Seed；
- 参考图路径和强度；
- 输出文件路径；
- 是否为图生图、局部重绘或 Director 结果。

原图、编辑结果和中间结果应保存成不同文件，不要让 AI 覆盖原始图片。

## 八、费用和确认习惯

以下操作可能消耗 NovelAI 资源：

- 文生图；
- 图生图；
- 局部重绘；
- Vibe 编码和使用；
- Director 工具；
- 专用放大；
- 高分辨率和多样本生成。

推荐的安全说法：

```text
先估算消耗，展示模型、尺寸、steps、样本数和预计 Anlas；没有我的确认不要生成。
```

单张小图测试通过后，再考虑批量或高分辨率操作。

## 九、常见问题

### AI 说找不到 Skill

检查：

```powershell
openclaw skills list
openclaw skills info openclaw-novelai
openclaw skills check
```

确认解压目录的根部直接有 `SKILL.md`，并且 Skill 已安装到当前 Agent，而不是只放在下载目录里。

### MCP 工具列表为空

依次检查：

1. `uvx` 是否能在终端找到；
2. Python 是否为 3.13；
3. OpenClaw Gateway 是否在配置 Token 的环境中启动；
4. 是否重启了 Gateway；
5. 沙箱是否允许 `bundle-mcp`；
6. `openclaw mcp doctor novelai-image --probe` 的错误信息。

### 返回 401

Token 缺失、过期或没有传给 MCP Server。不要把 Token 发到聊天里；重新检查用户环境变量和 Gateway 的启动环境。

### 返回 402

订阅或 Anlas 不足。不要自动重试，先查询账户和费用。

### 返回 400

通常是模型、图片、遮罩、尺寸或参数不匹配。让 AI 展示工具签名和脱敏后的错误字段。

### 返回 429

通常是并发或频率限制。停止并行生成，等待后再做一次小规模尝试。

### GLM-4.6 有 200 但没有文字

当前实测 GLM-4.6 的流式聊天正常，非流式请求可能返回 HTTP 200 但空文本。要求 OpenClaw 使用流式输出；如果宿主强制非流式，可以先换用 Xialong。

### 专用放大返回 404

当前 NovelAI 专用 `/ai/upscale` 路径可能已经不可用。不要无限重试；改用更高分辨率图生图或本地放大器，并明确这不是同一种处理。

## 十、推荐的首次启动指令

把压缩包和下面这段话一起交给朋友的 AI：

```text
请先解压并阅读 README.md、SKILL.md、docs/完整使用手册.md 和 COMPATIBILITY.md。

先检查当前 OpenClaw、Python、uv、uvx、Skill 搜索路径和 MCP 配置，不要立即安装、修改配置或生成图片。不要索要、打印或记录 NOVELAI_TOKEN 的值，只检查它是否存在于安全环境中。

请列出：
1. 当前已安装的 OpenClaw 版本；
2. Python 和 uvx 版本；
3. Skill 是否已加载；
4. NovelAI 文本模型是否已配置；
5. NovelAI Image MCP 是否能完成 doctor/probe；
6. 还缺哪些依赖或权限。

先给出准备执行的操作和风险，等我确认后再安装或修改。配置完成后，先做 MCP 工具发现和账户查询，不要直接批量生成。
```
